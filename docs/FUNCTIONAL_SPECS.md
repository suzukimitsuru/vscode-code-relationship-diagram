## 1. 概要

### 1.1 目的

VSCode Code Relationship Diagramは、ワークスペース全体のコードシンボルとその関係を分析し、インタラクティブなマルチビューグラフで可視化する拡張機能です。

### 1.2 主要機能

- **多言語対応**: VSCodeの言語プロバイダーを介して100以上のプログラミング言語に対応
- **3つの可視化ビュー**: ファイル依存関係、階層構造、呼び出しグラフ
- **ディレクトリグループ化**: ファイルをディレクトリ階層で整理する機能
- **エクスポート機能**: PNGおよびスタンドアロンHTMLエクスポート
- **大規模対応**: 数千ファイルのプロジェクトに対応する適応型レンダリング
- **差分更新**: ファイル変更のスマートな差分ベース処理

### 1.3 システム要件

- **VSCode**: 1.96.0以上
- **プラットフォーム**: macOS (arm64/x64), Windows (x64), Linux (x64)
- **Node.js**: 18/20/22 (VSCode組み込み)

## 2. インストールと起動

### 2.1 インストール方法

1. VSCodeマーケットプレイスから「Code Relationship Diagram」を検索
2. 「インストール」をクリック
3. VSCodeを再読み込み

### 2.2 起動条件

拡張機能は、ワークスペースに`.vscode/crd.duckdb`ファイルが存在すると自動的に起動します。

初回実行時は、このファイルは自動的に作成されます。

## 3. 基本操作

### 3.1 コマンド一覧

拡張機能は2つの主要コマンドを提供します：

#### a) `Code Relationship Diagram: Examine Relationships`

**目的**: コードベース全体を分析し、シンボルと関係を抽出してデータベースに保存

**実行方法**:
1. コマンドパレット (`Cmd+Shift+P` / `Ctrl+Shift+P`) を開く
2. 「Code Relationship Diagram: Examine Relationships」を入力
3. Enterキーを押す

**処理内容**:
- ワークスペース内のすべてのコードファイルを列挙
- 各ファイルのシンボル (クラス、関数、変数など) を抽出
- シンボル間の依存関係を分析
- すべてのデータをDuckDBデータベースに保存

**進捗表示**:
```
Examining Relationships... 45% (ETA: 01:23)
```

#### b) `Code Relationship Diagram: Show Diagram`

**目的**: データベースから読み込んだデータをインタラクティブなグラフで可視化

**実行方法**:
1. コマンドパレット (`Cmd+Shift+P` / `Ctrl+Shift+P`) を開く
2. 「Code Relationship Diagram: Show Diagram」を入力
3. Enterキーを押す

**処理内容**:
- データベースからシンボルと関係を読み込み
- 3つの可視化ビュー (ファイル依存関係、階層構造、呼び出しグラフ) を生成
- webviewパネルにグラフを表示

### 3.2 ワークフロー

**初回分析**:
1. `Examine Relationships` コマンドを実行
2. 分析完了を待つ (プロジェクトサイズに応じて数分)
3. `Show Diagram` コマンドを実行
4. グラフビューで可視化を確認

**差分更新** (ファイル変更後):
1. コードを編集・保存
2. `Examine Relationships` コマンドを実行
3. 変更されたファイルのみが再分析される (高速)
4. `Show Diagram` コマンドで最新の状態を確認

## 4. 可視化ビュー

### 4.1 ビュー1: ファイル依存関係

**目的**: ファイル間の依存関係のみを表示

**表示内容**:
- **ノード**: ファイル
- **エッジ**: ファイル間のインポート/参照関係
- **エッジの太さ**: 関係の数に比例
- **エッジの色**: 関係の密度を示すグラデーション

**レイアウト**: COSE (物理ベースの力学レイアウト)

**操作**:
- **ディレクトリグループ化ボタン**: ファイルをディレクトリ階層でグループ化
- **ズーム**: マウスホイール / ピンチジェスチャー
- **パン**: ドラッグ
- **ダブルクリック**: ファイルを開く

**使用例**:
- プロジェクトのモジュール構造を理解
- 密結合しているファイルを特定
- 循環依存を発見

### 4.2 ビュー2: 階層構造

**目的**: シンボルの包含階層を表示

**表示内容** (データセットサイズに応じて適応):

- **小規模データセット** (≤ 5000ノード):
  - **ノード**: すべてのシンボル (ファイル、クラス、メソッド、変数など)
  - **エッジ**: シンボル間の関係
  - **レイアウト**: Dagre (階層的な有向非巡回グラフ)

- **大規模データセット** (> 5000ノード):
  - **ノード**: ファイルのみ
  - **エッジ**: ファイル間の関係
  - **レイアウト**: COSE (高速な力学レイアウト)

**操作**:
- **Expand All ボタン**: すべてのノードを展開
- **Collapse All ボタン**: すべてのノードを折りたたむ
- **ディレクトリグループ化ボタン**: ファイルをディレクトリでグループ化

**使用例**:
- クラスの構造を理解
- メソッドの依存関係を確認
- 特定のシンボルの使用箇所を追跡

### 4.3 ビュー3: 呼び出しグラフ

**目的**: 関数/メソッド呼び出し関係を表示

**表示内容** (データセットサイズに応じて適応):

- **小規模データセット** (≤ 5000ノード):
  - **ノード**: すべてのシンボル
  - **エッジ**: シンボル間の呼び出し関係
  - **レイアウト**: Dagre (階層的)

- **大規模データセット** (> 5000ノード):
  - **ノード**: ファイルのみ
  - **エッジ**: ファイル間の呼び出し関係
  - **レイアウト**: COSE (高速)

**操作**:
- **方向切り替えボタン**: 縦 (上から下) / 横 (左から右) レイアウトを切り替え
- **ディレクトリグループ化ボタン**: ファイルをディレクトリでグループ化

**使用例**:
- 関数呼び出しフローを理解
- エントリーポイントから実行パスを追跡
- 未使用のメソッドを発見

### 4.4 ディレクトリグループ化機能

**目的**: ディレクトリ構造でファイルを視覚的に整理

**動作**:
1. 「Dir: OFF」ボタンをクリック
2. ファイルが自動的にディレクトリ階層でグループ化される
3. ディレクトリノードが追加され、ファイルが内部に配置される

**視覚的結果**:
```text
┌─ src/ ──────────────────────┐
│  ┌─ main.ts ─┐              │
│  └───────────┘              │
│  ┌─ utils/ ───────┐         │
│  │  ┌─ helper.ts ─┐         │
│  │  └─────────────┘         │
│  └─────────────────┘        │
└──────────────────────────────┘
```

**利点**:
- 大規模プロジェクトでの可読性向上
- ファイルの論理的なグループ化
- プロジェクト構造の理解が容易

## 5. インタラクティブ機能

### 5.1 ファイルナビゲーション

**ダブルクリック / Ctrl+クリック / Cmd+クリック**:

ノードをダブルクリックまたはCtrl/Cmd+クリックすると、対応するファイルがVSCodeエディタで開かれます。

**動作**:
- ファイルノード: ファイルの先頭行で開く
- シンボルノード: シンボルの定義行で開く

### 5.2 エッジツールチップ

**ホバー表示**:

エッジ (矢印) にマウスをホバーすると、詳細な関係情報がツールチップで表示されます。

**表示内容**:
- 参照元シンボル名と行番号
- 参照先シンボル名と行番号
- 最大10個の関係を表示 (それ以上は「... 他 N 関係」と表示)

**例**:
```
MyClass.getData → APIService.fetchData (line 42)
MyClass.saveData → APIService.postData (line 58)
... 他 5 関係
```

**クリックしてナビゲート**:

ツールチップ内の関係行をクリックすると、対応するファイルと行に移動できます：
- 左側 (参照元) をクリック: 参照元ファイルの行に移動
- 右側 (参照先) をクリック: 参照先ファイルの行に移動

### 5.3 ズームとパン

**ズーム**:
- マウスホイール: 上下にスクロール
- ピンチジェスチャー: トラックパッド (2本指)

**パン** (グラフ移動):
- ドラッグ: グラフの空白部分をドラッグ

**フィット**:
- すべてのノードがビューポートに収まるように自動調整

## 6. エクスポート機能

### 6.1 PNGエクスポート

**目的**: 現在のビューをPNG画像として保存

**実行方法**:
1. エクスポートメニューボタン (フロッピーディスクアイコン) をクリック
2. 「PNG」を選択
3. ブラウザのダウンロードダイアログで保存先を指定

**出力内容**:
- 現在のビュー全体 (すべてのノードとエッジ)
- 白い背景
- 高解像度 (プレゼンテーション用)

**ファイル名**:
```
code-relationship-file-deps.png
code-relationship-hierarchy.png
code-relationship-call-graph.png
```

### 6.2 HTMLエクスポート

**目的**: スタンドアロンHTMLファイルとして保存 (VSCode不要で開ける)

**実行方法**:
1. エクスポートメニューボタンをクリック
2. 「HTML」を選択
3. VSCodeの保存ダイアログで保存先を指定
4. 「Open File」または「Open in Browser」を選択

**出力内容**:
- 完全に機能するインタラクティブグラフ
- すべてのライブラリをCDNから読み込み
- データがインライン化

**利点**:
- VSCodeなしでブラウザで開ける
- チームメンバーと共有可能
- ドキュメントやレポートに埋め込み可能

**制限**:
- ファイルナビゲーション機能は無効 (VSCode APIに依存)
- PNGエクスポートのみ利用可能

## 7. 設定とカスタマイズ

### 7.1 ファイル関連付け

VSCodeワークスペース設定から読み込まれます：

```json
{
  "files.associations": {
    "*.ts": "typescript",
    "*.tsx": "typescriptreact",
    "*.js": "javascript",
    "*.jsx": "javascriptreact",
    "*.py": "python",
    "*.go": "go",
    "*.rs": "rust",
    "*.cpp": "cpp",
    "*.hpp": "cpp",
    "*.c": "c",
    "*.h": "c"
  }
}
```

**用途**:
- 分析対象のファイルを決定
- シンボル抽出用の言語判定
- ファイル監視のセットアップ

### 7.2 .gitignore統合

`.gitignore`ファイルが自動的に読み込まれ、以下のディレクトリ/ファイルが除外されます：

**デフォルト除外**:
- `.git/**`
- `.vscode/**`
- `.DS_Store`
- `node_modules/**`

**カスタム除外**:

プロジェクトルートに`.gitignore`ファイルを配置し、除外したいパターンを記述します：

```text
# ビルド出力
dist/
build/
*.js.map

# テストカバレッジ
coverage/
.nyc_output/

# 一時ファイル
*.tmp
*.log
```

### 7.3 テーマサポート

拡張機能は自動的にVSCodeのテーマ設定を検出し、グラフの色を調整します：

- **ダークテーマ**: 暗い背景色、明るいテキスト
- **ライトテーマ**: 明るい背景色、暗いテキスト

## 8. パフォーマンス

### 8.1 処理時間の目安

**テストプロジェクト**: 500ファイルのTypeScriptコードベース

| 操作 | 時間 | 備考 |
|------|------|------|
| ファイル列挙 | 0.5秒 | fast-globを使用 |
| シンボル抽出 | 15秒 | 500ファイル × 平均30ms |
| 関係抽出 | 45秒 | VSCode API呼び出し |
| データベース保存 | 2秒 | バッチ挿入 |
| グラフレンダリング | 1秒 | 2,000ノード, 3,000エッジ |
| **合計** | **63.5秒** | 完全な初回分析 |

**差分更新**: 単一ファイル変更

| 操作 | 時間 | 備考 |
|------|------|------|
| ファイル変更検出 | 0.1秒 | タイムスタンプ比較 |
| シンボル再抽出 | 0.03秒 | 単一ファイル |
| 関係更新 | 0.5秒 | 変更されたファイルのみ |
| データベース更新 | 0.1秒 | 単一ファイル更新 |
| **合計** | **0.73秒** | 差分更新 |

### 8.2 大規模プロジェクトの最適化

**適応型レンダリング**:

データセットサイズに応じてレンダリング方法が自動的に切り替わります：

- **小規模** (≤ 5000ノード): シンボルレベル詳細表示 + Dagreレイアウト
- **大規模** (> 5000ノード): ファイルレベルのみ + COSEレイアウト

**理由**: パフォーマンスと可読性のバランス

**推奨事項**:
- 初回インデキシング完了を待つ
- `.gitignore`で無関係なディレクトリを除外
- 他のVSCodeウィンドウを閉じる
- ファイルレベルビューのみを使用

## 9. トラブルシューティング

### 9.1 ノードが表示されない

**症状**: Webviewが空のグラフを表示

**原因**:
1. データ送信前にWebviewが初期化されていない
2. 転送中にチャンクデータが失われた
3. シンボル抽出が失敗した

**解決策**:
1. ブラウザコンソールでエラーをチェック
   - Webview Developer Tools を開く: `Cmd+Option+I` / `Ctrl+Shift+I`
2. `webviewReady`メッセージがログされているか確認
3. コンソールでノード数をチェック (DBと一致する必要がある)
4. `Examine Relationships`コマンドを再実行

### 9.2 DuckDBバインディングが見つからない

**症状**: ネイティブバインディングの読み込みエラー

```
Error: Cannot find module 'duckdb'
```

**原因**:
1. プラットフォーム/Node.jsバージョン用のバインディングがない
2. macOSでバイナリが署名されていない
3. バインディングファイルが破損している

**解決策**:
1. `/bindings`ディレクトリで一致するファイルをチェック
   ```bash
   ls bindings/
   # duckdb-{platform}-{arch}-v{version}.node が存在するか確認
   ```
2. macOSバインディングで署名を確認
   ```bash
   codesign -v bindings/duckdb-darwin-arm64-v20.node
   ```
3. 拡張機能を再ダウンロードまたはバインディングを再ビルド

### 9.3 パフォーマンスが遅い

**症状**: 長い分析時間、UIフリーズ

**原因**:
1. 非常に大きなコードベース (10,000以上のファイル)
2. 複雑な関係 (100,000以上のエッジ)
3. 言語サーバーが準備できていない

**解決策**:
1. 初回インデキシングの完了を待つ
   - VSCodeステータスバーで確認
2. `.gitignore`で無関係なディレクトリを除外
   ```text
   node_modules/
   dist/
   build/
   vendor/
   ```
3. 他のVSCodeウィンドウを閉じる
4. ファイルレベルビューのみを使用 (シンボルビューを無効化)

### 9.4 エクスポートボタンが動作しない

**症状**: エクスポートメニューが開かない、またはクリックしても反応しない

**原因**:
- 複数ビューのID競合 (v0.1.28以前のバージョン)

**解決策**:
- v0.1.29以降にアップデート (各ビューに独立したエクスポートメニュー)

### 9.5 ファイル変更が反映されない

**症状**: コードを変更しても、グラフが更新されない

**原因**:
- `Examine Relationships`コマンドを再実行していない

**解決策**:
1. コードを編集・保存
2. `Code Relationship Diagram: Examine Relationships`コマンドを実行
3. 差分更新が完了するまで待つ
4. `Code Relationship Diagram: Show Diagram`コマンドで最新の状態を確認

## よくある質問 (FAQ)

### Q1: どのプログラミング言語がサポートされていますか？

A: VSCodeの言語プロバイダーを介して100以上の言語に対応しています。主要言語には以下が含まれます：
- JavaScript/TypeScript
- Python
- Java
- C/C++
- C#
- Go
- Rust
- PHP
- Ruby
など

### Q2: データベースファイルは削除しても安全ですか？

A: はい、`.vscode/crd.duckdb`ファイルを削除しても安全です。次回`Examine Relationships`コマンドを実行すると、自動的に再作成されます。

### Q3: エクスポートしたHTMLファイルをカスタマイズできますか？

A: はい、エクスポートされたHTMLファイルは通常のHTMLファイルなので、テキストエディタで開いて編集できます。CSSスタイルやJavaScriptをカスタマイズして、必要に応じて調整できます。

### Q4: 大規模プロジェクトでパフォーマンスを改善するには？

A: 以下の方法でパフォーマンスを改善できます：
- `.gitignore`で無関係なディレクトリを除外
- VSCodeの初回インデキシング完了を待つ
- 他のVSCodeウィンドウを閉じる
- ファイルレベルビューのみを使用

### Q5: グラフをプレゼンテーションで使用できますか？

A: はい、PNGエクスポート機能を使用して高解像度の画像を生成し、プレゼンテーションに埋め込むことができます。また、HTMLエクスポートを使用してインタラクティブなデモを共有することもできます。
