## 重要な技術的決定

拡張機能の設計における重要な技術的決定については、以下のセクションを参照してください：

1. **シンボルID生成戦略** - [実装仕様書 § 3.1.b](IMPLEMENTATION_SPECS.md#b-シンボルモデル-extractsymbolts)
   - 形式: `${parentId}/${kind}.${name}@${hash}`
   - ファイル移動やリネームに対して安定

2. **Webview初期化ハンドシェイク** - [実装仕様書 § 5.1.b](IMPLEMENTATION_SPECS.md#b-webview初期化ハンドシェイク)
   - 双方向通知プロトコル
   - 初期化前のpostMessageでデータ損失を防止

3. **チャンク化データ転送** - [実装仕様書 § 5.3](IMPLEMENTATION_SPECS.md#53-チャンク化データ転送)
   - 5000要素ごとにチャンク分割
   - postMessageサイズ制限を回避

4. **適応型レンダリング** - [実装仕様書 § 7.3](IMPLEMENTATION_SPECS.md#73-適応型レンダリング)
   - データセットサイズに応じてレンダリング方法を切り替え
   - 小規模 (≤ 15,000ノード): 全4レベル使用可能（File + Symbol含む）
   - 中規模/大規模 (> 15,000ノード): Directory Only / Directory + File / File Only のみ

5. **DuckDBバインディング動的ロード** - [実装仕様書 § 6.1](IMPLEMENTATION_SPECS.md#61-duckdbネイティブバインディング)
   - プラットフォーム × Node.jsバージョンごとに最適なバインディングを選択
   - macOSでは自動コード署名

## 貢献ガイド

プロジェクトへの貢献を検討している場合は、以下の手順をお勧めします：

1. **機能仕様書を読む** - ユーザー機能を理解する
2. **実装仕様書を読む** - アーキテクチャとコード構造を理解する
3. **DUCKDB_BINDINGS.md を読む** - 必要に応じてネイティブバインディングをビルドする
4. **claude.md を参照する** - 開発ガイドラインとコーディング規約を確認する
5. **コードを書き始める** - 実装仕様書を参考に開発を進める
