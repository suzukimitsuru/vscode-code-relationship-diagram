# コード関係図 仕様書

## 1.要求仕様

コードの構造を把握するために、コードを元にコード関係図を描画する。

- コード関係図は、階層構造(フォルダ/ファイル/シンボル)の参照関係を、グラフ構造で描画する。
- Living Document として、描画とコードを連携し、図からもコードの編集し易く、管理し易い機能とする。

---

## 2.機能仕様書

### 2-1.図の構造

コード関係図は、中心点から

### 2-1-1.図の構成要素

### 2-1. ノード

#### 2-1-1. ノードの種類

- **ファイルノード**: ソースファイルを表す
- **シンボルノード**: ファイル内のシンボル(関数・クラス・変数等)を表す

#### 2-1-2. ノードのサイズ

- シンボルノードのサイズは、そのノードが表すコードの行数(lineCount)によって決まる
- **シンボルノード**: 行数が増えるにつれて大きくなる
- **ファイルノード**: 掴みやすい様に、シンボルノードの 100 行分のサイズとする
- スケールは√スケールを用いて、極端なサイズ差を抑制する

#### 2-1-3. ノードの視覚的区別

- ファイルノードとシンボルノードは、形状または色によって視覚的に区別する
- ノードの色は保守性スコアを反映する(詳細は circle-diagram.md §2 参照)

---

### 2-2. エッジ

#### 2-2-1. エッジの対象

- エッジはシンボルノード間の参照関係を表す(シンボル A がシンボル B を参照する)
- シンボル間の参照をエッジとして表示する(ファイル内の内部参照も表示する)

#### 2-2-2. エッジの方向

- エッジは「参照しているシンボル → 定義しているシンボル」の方向に矢印を付ける

#### 2-2-3. エッジの太さ

- エッジの太さは参照数(reference count)が多いほど太くなる(対数スケール)

#### 2-2-4. シンボルノードを非表示にした場合の集約

- シンボルノードを非表示にした場合、シンボル間のエッジはファイルノード間のエッジに集約して表示する
- ファイルノード間のエッジに集約した場合は、同一ファイル内のシンボル間参照はエッジとして表示しない

---

### 2-3. ファイルノードの配置

#### 2-3-1. BFS 深度リング配置

- 深度リング: 複数の同心円に配置する
  - 深度0: 描画エリアの中心
  - 深度1: 内側リング
  - 深度d: d番目のリング
- エントリポイントのファイルノード
  - エントリポイントファイル(他ファイルから参照されない、または命名規則で判定)を深度 0 として中心に配置する
  - エントリポイントが複数存在する場合は、深度1のリングに配置する
- エントリポイント以外のファイルノード
  - BFS(幅優先探索)でエントリポイントから参照されるファイルを辿り、深度ごとの深度リングに配置する
  - 複数のエントリポイントから参照される場合は、平均の深度の深度リングに配置する

#### 2-3-2. 同一リング内の並び順

- 同一深度(同一リング)内では、被参照数(in-degree)が多いファイルを先に並べる

#### 2-3-3. リングあふれ(overflow)

- 同一リングに配置するノードが多く間隔が不足する場合、余分なノードを隣接するサブリング(深度 d-1 と d+1 の間)に振り分ける
- サブリングへの振り分けは被参照数の昇順(少ないものを外側へ)で行う

#### 2-3-4. 到達不能ファイルの配置

- エントリポイントから BFS で到達できないファイル(孤立ファイル)は、最も外側のリングの外側(最大深度 + 1 のリング)に配置する

---

### 2-4. シンボルノードの配置

#### 2-4-1. ファイル内の初期配置

- 深度リング: 複数の同心円に配置する
  - 深度0: ファイルノードの中心
  - 深度1: 内側リング(公開シンボル)
  - 深度d: d番目のリング
- シンボルノードは、所属するファイルノードを中心とした深度リングに配置する
- 公開(public)シンボルを

- 公開(public)シンボル
  - 深度1の深度リングに配置する
- 非公開シンボル
  - BFS(幅優先探索)でエントリポイントから参照されるファイルを辿り、深度ごとの深度リングに配置する
  - 複数のエントリポイントから参照される場合は、平均の深度の深度リングに配置する

#### 2-4-2. 同一リング内の並び順

- 同一深度(同一リング)内では、被参照数(in-degree)が多いシンボルを先に並べる

#### 2-4-3. リングあふれ(overflow)

- 同一リングに配置するノードが多く間隔が不足する場合、余分なノードを隣接するサブリング(深度 d-1 と d+1 の間)に振り分ける
- サブリングへの振り分けは被参照数の昇順(少ないものを外側へ)で行う

#### 2-4-4. 到達不能シンボルの配置

- 公開シンボルから BFS で到達できないシンボル(孤立シンボル)は、最も外側のリングの外側(最大深度 + 1 のリング)に配置する

---

### 2-5. 力学シミュレーション

初期配置で大まかな位置に配置し、力学シミュレーションで調整する。

#### 2-5-1. 働く力

シミュレーション中に以下の力が働く:

| 力の種類 | 作用 |
| ------- | ---- |
| エッジ引力 | 接続されたノード間をエッジの太さに比例した力で引き寄せる |
| ノード間斥力 | 全ノード間に働く反発力(ノードサイズに比例) |
| 親ファイル引力 | シンボルノードを所属ファイルノードへ引き寄せる(シンボルノード非表示の場合には無効) |
| 減衰(摩擦) | ノードの速度を減衰させてシミュレーションを収束させる |
| 径方向スプリング | ファイルノードを BFS 深度リングの半径へ引き戻す(同心円構造の維持) |

- ※ エッジ引力の対象はシンボル表示時はシンボルノード間、シンボル非表示時はファイルノード間のエッジに切り替わる(§2-2-4 参照)

#### 2-5-2. シミュレーション中のノード挙動

- **ファイルノード**: 可動。径方向スプリングにより所属 BFS 深度リングの半径を維持する(半径方向は維持、角度方向は自由に動ける)
- **シンボルノード**: 可動。親ファイル引力により所属ファイルノードの周囲に留まる

#### 2-5-3. 収束と停止

- シミュレーションは、全ノードの移動量が閾値以下になると自動的に停止する
- ユーザーが手動でシミュレーションを停止することもできる
- 停止後もユーザーが再開できる

## 3. 実装仕様

機能仕様(§2)を具体的な実装に落とし込む際に決定が必要な項目を以下に列挙する。
各項目は言語・ライブラリ・パフォーマンス要件に応じて実装時に選択する。

### 3-1. シンボルの分類基準

#### 3-1-1. エントリポイントの検出

- 他ファイルから参照されないファイルは、エントリポイントとする
- 命名規則パターン(`main`, `activate`, `index`, `App` 等)の言語別定義
- フレームワーク特有アノテーションの検出方法

**実装値** (`src/relationship/cosmosAdapter.ts:157-161`):

- 検出条件: `(inDegree === 0 && outDegree > 0) || naming pattern match`
- 命名規則パターン: `main|index|app|server|start|activate|bootstrap|init`
- 対応ファイル拡張子: `.ts|.js|.tsx|.jsx|.py|.go|.rs|.java|.cs|.cpp|.c`

#### 3-1-2. 公開シンボルの判定基準

- TypeScript/JavaScript: `export` キーワード
- Python: `_` プレフィックスなし
- Java/C#: `public` アクセス修飾子

### 3-2. ノードとエッジの視覚パラメータ

#### 3-2-1. ノードサイズ

- スケール関数は√スケールとする
- ファイルノードのサイズは 100 行 = 12px として固定し、定数で定義する

**実装値** (`src/relationship/cosmosAdapter.ts:118-121`):

- ファイルノード基準行数: `FILE_NODE_BASE_LINES = 100`
- ファイルノードサイズ: `FILE_NODE_FIXED_SIZE = 12` (px)
- シンボルノード計算式: `size = FILE_NODE_FIXED_SIZE × √(lineCount / FILE_NODE_BASE_LINES)`
  - 100行時: 12px（ファイルノードと同サイズ）
  - 0行時: 0px（ノードは点として描画）
- ディレクトリノード: 固定値 12px

#### 3-2-2. エッジ幅

- 参照数からエッジ幅への変換関数
- エッジ幅の最小値・最大値

**実装値** (`src/relationship/cosmosAdapter.ts:574-577`):

- 計算式: `width = min(1 + log₂(relationshipCount + 1) × 2, 10)`
- 最小値: `1` (px)
- 最大値: `10` (px)
- エッジ色(通常): `0x3498DB`(青)
- エッジ色(循環参照): `0xFF4444`(赤)

### 3-3. 配置パラメータ

- リング間の間隔(ringSpacing)のデフォルト値
- 同一リング内のノード間の最小間隔(minNodeGap)
- サブリング位置: 隣接する主リングの中間点 `(radius_d + radius_{d+1}) / 2`

**実装値** (`src/webview/graphView.ts:96-103`):

- ファイルノード リング間隔:      `FILE_RING_SPACING = 220` (px)
- ファイルノード 最小ノード間隔:  `FILE_RING_MIN_NODE_GAP = 60` (px)
- シンボルノード リング間隔:      `SYMBOL_RING_SPACING = 60` (px)
- シンボルノード 最小ノード間隔:  `SYMBOL_RING_MIN_NODE_GAP = 16` (px)
- サブリング位置: 主リング間の中間点（= リング間隔の 1/2 オフセット）

### 3-4. 力学シミュレーションのパラメータ

- Barnes-Hut θ 閾値は 1.2 として実装し定数で定義する
- 斥力の強さ(repulsionStrength)
- エッジスプリングの基本強度と参照数あたりの増分(linkSpringBase, linkSpringPerWidth)
- エッジスプリングの自然長(linkRestLength)
- 親ファイル引力の強さ(symbolParentSpring)
- 親ファイルとの自然長(symbolParentRestLength)
- 減衰係数(friction)
- ノードの最大速度(maxVelocity)
- 収束判定閾値(convergenceThreshold)
- 最大シミュレーションステップ数(maxTicks)
- ファイルノードの径方向スプリング強度(fileRadialSpring)
- ノード数に応じたパラメータ動的調整は無いものとする

**実装値** (`src/webview/graphView.ts:113-143`):

- 斥力強度: `SIM_REPULSION_STRENGTH = 150`
- 最大斥力距離: `SIM_REPULSION_MAX_DIST = 500` (px)
- リンク引力基本強度: `SIM_LINK_SPRING_BASE = 0.005`
- リンク引力(幅あたり): `SIM_LINK_SPRING_PER_WIDTH = 0.003`
- エッジの自然長: `SIM_LINK_REST_LENGTH = 120` (px)
- 親ファイル引力: `SIM_SYMBOL_PARENT_SPRING = 0.03`
- 親ファイルとの自然長: `SIM_SYMBOL_PARENT_REST_LENGTH = 50` (px)
- 減衰係数(摩擦): `SIM_FRICTION = 0.85`
- ノード最大速度: `SIM_MAX_VELOCITY = 3`
- 収束判定閾値: `SIM_CONVERGENCE_THRESHOLD = 0.01`
- 最大シミュレーションステップ数: `SIM_MAX_TICKS = 3000`
- Barnes-Hut θ: `SIM_BARNES_HUT_THETA = 1.2`
- 径方向スプリング強度: `SIM_FILE_RADIAL_SPRING = 0.02`

### 3-5. レンダリング

- Cosmos.gl を使用する場合の `enableSimulation` 設定(内蔵シミュレーション vs 自前シミュレーション)
- `setPointPositions()` / `setLinkWidths()` / `setLinkArrows()` / `setPointColors()` の呼び出しタイミング
- アニメーションループの実装方法(`requestAnimationFrame`)
- GPU レンダリングの座標空間サイズ(spaceSize)

**実装値** (`src/webview/graphView.ts:1357-1361`):

- ライブラリ: Cosmos.gl + プリセットレイアウト
- `enableSimulation`: `false`(事前計算座標を使用)
- 座標空間サイズ: `spaceSize = 4096` (px)
- アニメーション: `requestAnimationFrame` でフレーム同期

### 3-6. シンボル非表示時の集約ロジック

- ファイルレベルでの参照数の集計方法
- 同一ファイル内参照の除外処理の実装

**実装値** (`src/relationship/cosmosAdapter.ts:528-565`):

- 集計方式: `aggregateFileRelationships()` でシンボル関係をファイル関係に集約
- 同一ファイル内参照: 除外(`if (sourcePath === targetPath) continue`)
- 参照数集計: 同じファイル対 `(sourcePath, targetPath)` の参照数で集計
- エッジ方向: 参照元ファイル → 定義先ファイル

### 3-7. 可変深度範囲

- 最大深度(maxDepth)のデフォルト値と UI 操作方法
- 深度変更時のノード追加・削除の差分更新方法
- シミュレーション再開時の既存ノード位置の保持方法

**実装値** (`src/webview/graphView.ts:387, 477-478`):

- 最大深度デフォルト値: `maxDepth = 100`(無限深度の意味)
- UI操作: スライダーで `minDepth` / `maxDepth` を調整可能
- 深度表示: `maxDepth >= 100` の場合は `∞` 記号で表示
- 差分更新: 深度変更時はノードの `visibility` を動的に切り替え
- シミュレーション: 深度変更後、既存ノード位置を保持(全体再計算なし)
